This phase resolves transactional ambiguity between **Currency Conversion** and **Inter-Wallet Transfers** by adopting the industry-standard **Multi-Sub-Wallet / Account Pots** pattern (modeled after Revolut Pockets and Monzo Pots). It empowers the user to create multiple wallets within the same currency (e.g., *USD Main*, *USD Savings*, *IDR Daily*), enforces strict **1:1 same-currency transfers**, eliminates cross-currency leakage in the transfer workflow, and refactors wallet cards into a horizontal scrollable view with quick currency filters and an integrated `+ Add Wallet` modal trigger. Additionally, it polishes action button labels with locale-aware thousand separators.

## 📋 2. Detailed Technical Specifications

### 2.1 Track A: Schema & Domain Invariants
1. **Prisma Model Update (`schema.prisma`):**
   - Remove `@@unique([userId, currency])`.
   - Add `name String @default("Main")` to `model Wallet`.
   - Execute `npx prisma db push` (and refresh SQLite seeder if needed).
2. **Domain Entity Update (`Wallet.ts`):**
   - Accept optional `name?: string` in constructor and `toJSON()`.
3. **Use Case: `CreateWalletUseCase`:**
   - DTO: `{ userId: string; currency: string; name: string }`.
   - Invariants: Supported currency check, non-empty name, trims whitespace.
4. **Use Case: `TransferFundsUseCase`:**
   - Invariant: `if (fromWallet.currency !== toWallet.currency) throw new CurrencyMismatchTransferError()`.
   - Financial Math: Strictly 1:1 (`amountTransferred === receivedAmount`, `effectiveRate === 1.0`).
   - Audit Record: Strictly emit `type: 'TRANSFER_OUT'` and `type: 'TRANSFER_IN'` (never `CONVERT_*`).
5. **Use Case: `ConvertFundsUseCase` Cross-Currency Invariant:**
   - Invariant: `if (fromWallet.currency === toWallet.currency) throw new SameCurrencyConversionError()`.
   - Prevents artificial 1:1 rates in FX conversion; reserves same-currency movements strictly for `TransferFundsUseCase`.

### 2.2 Track B: REST API Endpoints
| Method | Path | Payload | Success Response |
|---|---|---|---|
| `POST` | `/api/wallets` | `{ currency: string, name: string }` | `{ success: true, data: { wallet } }` |
| `POST` | `/api/wallets/transfer` | `{ fromWalletId, toWalletId, amount, notes }` | `{ success: true, data: { referenceId, ... } }` |

### 2.3 Track C: UI & Frontend Transformation
1. **Horizontal Scrollable Carousel (`WalletCardGrid.tsx`):**
   - Replace rigid vertical/5-column grid with a scrollable card row: `flex gap-4 overflow-x-auto pb-4 scrollbar-thin`.
   - Include currency filter chips at top: `[All] [USD] [EUR] [GBP] [SGD] [IDR]`.
   - **Hybrid UX Pattern:** Primary quick-action button `[+ New Pocket]` situated directly in the header toolbar (accessible instantaneously without scrolling or filter restrictions), complemented by an interactive dashed `+ New Sub-Pocket` card at the carousel tail as secondary visual affordance.
2. **Create Wallet Modal Dialog:**
   - Form fields: Currency selector dropdown (`USD`, `EUR`, `GBP`, `SGD`, `IDR`), Wallet Name/Label input (e.g., *"Emergency Fund"*, *"Trading Pocket"*).
3. **Transfer Form Dropdown Guard:**
   - In `WalletActionWorkbench.tsx` under `activeTab === 'transfer'`, automatically filter `toWalletOptions` to only list wallets sharing the same currency as `fromWallet`.
4. **Submit Button Label Formatting:**
   - Format source amount using currency-specific decimals:
     `Convert ${numAmount.toLocaleString('en-US', { minimumFractionDigits: decimals })} ${fromWallet.currency}...`
   - Resolves `Convert 1000000000 IDR...` ➔ `Convert 1,000,000,000 IDR...`.
5. **Convert Form Dynamic Cross-Currency Guard:**
   - In `WalletActionWorkbench.tsx` under `activeTab === 'convert'`, automatically filter `convertToOptions` to strictly exclude wallets sharing the same currency as `fromWallet`. Includes auto-fallback resolver so changing Sell pocket immediately aligns the Buy dropdown without invalid pairings.
