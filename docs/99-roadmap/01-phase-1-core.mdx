This phase established the foundational pure domain models, currency precision math utilities, SQLite persistence via Prisma, initial simulated user provisioning, and deposit/withdrawal application use cases.

---

## 🎯 1. Scope & Intent

1. **Domain Model & Invariants:**
   - Framework-agnostic `Wallet` and `Transaction` domain entities.
   - Financial decimal utility `roundCurrency` (`JPY` = 0 decimals, other fiats = 2 decimals).
   - Domain error hierarchy: `InsufficientBalanceError`, `InvalidAmountError`, `WalletNotFoundError`.
2. **Persistence Layer (Prisma SQLite):**
   - Relational schema in `prisma/schema.prisma` with `User`, `Wallet`, and `Transaction` models.
   - Database push and seeding script allocating initial wallets to simulated user `Indra SB` (`USD: $1,000`, `EUR: €500`, `GBP: £300`, `SGD: S$400`, `JPY: ¥50,000`).
3. **Core Use Cases:**
   - `DepositFundsUseCase`: Validates `amount > 0`, credits wallet balance, records `DEPOSIT` transaction.
   - `WithdrawFundsUseCase`: Validates `amount > 0`, guards against overdraft (`InsufficientBalanceError`), debits wallet balance, records `WITHDRAWAL` transaction.
   - `GetWalletsUseCase`: Queries user wallets and builds currency balance map.
4. **Unit Test Suite (Vitest):**
   - High-speed in-memory repository tests executing in sub-200ms.
